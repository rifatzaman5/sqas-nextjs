SQASOverview · 03

What is SQAS?

A web-based attendance management system where teachers generate a time-limited QR code per class and students scan it from their phone — with location, device, and one-time-use checks running in the background.

Web App QR-based Geo-fenced Device-bound Real-time Role-based Mobile-friendly

Three users, one platform

  • Admin — manages students, teachers, subjects, timetable, settings.
  • Teacher — generates QR per class, monitors live attendance.
  • Student — scans QR, views own attendance history.

SQASProblem · 04

Why we built it

Problems with traditional roll-call

  • Takes 5–10 minutes from every class.
  • Proxy attendance is easy (sirf naam call hota hai).
  • Paper registers lost or tampered.
  • Reports manually banti hain — slow, error-prone.
  • No real-time visibility for students/admin.

Our objectives

  • Speed — full class attendance < 60 seconds.
  • Anti-proxy — device + GPS + one-time QR.
  • Transparency — students see their own records live.
  • Reporting — per-subject, per-date filters in 1 click.
  • Cloud-native — scales without infrastructure work.

SQASWhy these tools · 06

Why we chose this stack

Next.js, plain React kyun nahi?
Next.js mein frontend + backend (API routes) ek hi project. Express server alag nahi banana padta. SSR built-in → SEO + fast first paint. Vercel par one-click deploy.
Supabase, MongoDB kyun nahi?
Attendance data relational hai (students ↔ subjects ↔ timetable ↔ attendance). SQL joins is use-case ke liye banaye gaye hain. Plus RLS + auto-generated REST APIs free.
JWT vs sessions?
Stateless — server pe session table nahi chahiye. Token mein hi user info. HttpOnly cookie → XSS-safe.

SQASArchitecture · 07

Three-tier serverless architecture

Layers

  • Presentation — React pages (client + server components).
  • Application — Next.js API routes (serverless functions on Vercel).
  • Data — Supabase Postgres with Row-Level Security.

Why serverless?

  • Auto-scales with load.
  • No server maintenance.
  • Pay-per-request (free tier for academic project).

SQASRoles · 09

Three roles, RBAC-enforced

Admin
• Full CRUD on all entities
• View all attendance
• Configure geofence + QR window
• Reset student device binding
Teacher
• Generate QR for own classes
• Live attendee list (5s polling)
• View own subjects' attendance
• No access to other teachers' data
Student
• Scan QR / enter code
• View own attendance only
• Device locked to first login
• No CRUD access

How RBAC works

JWT mein role claim sign hota hai. Har API route role check karta hai — student APIs query mein student_id = session.id hard-inject karti hai. Cross-user data leak impossible.

SQASWorkflow · 10

QR lifecycle — one class, end to end

1Teacher login → system auto-detects today's active or upcoming slot.
2Click "Generate QR" → backend creates unique token, expires in 15 min.
3QR rendered with deep-link URL payload. Countdown timer starts.
4Student scans QR with any phone camera/app — URL opens.
5Auto-submit fires with token + GPS + device_id.
6Backend runs 6 checks — pass → attendance row inserted.
7Teacher's live list updates within 5 seconds (polling).

SQASSecurity · 11

Six-layer anti-proxy defense

1. Token validity
Token DB mein exist + expires_at future mein hona chahiye.
2. Time window
Class start −10 min se end +15 min tak hi accept.
3. Geofence
Student ka GPS configured radius ke andar hona chahiye.
4. Device binding
First login pe device_id save. Aage se sirf wahi device accept.
5. One-time use
Same QR + same student → UNIQUE constraint rejects.
6. Duplicate day
Same class same date → UNIQUE constraint rejects.

Plus auth-layer security

  • Passwords bcrypt-hashed (cost 10).
  • JWT in HttpOnly + Secure + SameSite=Lax cookies.
  • Supabase RLS on every table; service-role key server-only.
  • Next.js parameterized queries → SQL injection impossible.

SQASChallenges · 15

Challenges & how we solved them

QR scanners raw text dikhate the, URL nahi kholte the.
QR payload full URL banayi (https://…/mark-attendance?token=XXX) — har scanner ab browser khol deta hai.
Vercel UTC mein, Pakistan dates ghalat aa rahe the.
Asia/Karachi timezone explicitly use kiya. Now all dates production-accurate.
Student same QR refresh kar ke proxy mark karta tha.
qr_token_scans ledger table add ki UNIQUE(token, student) constraint ke saath. Replay impossible.
Doosre ke phone se attendance possible thi.
Device binding: localStorage UUID + DB persistence + mismatch reject + admin reset.
