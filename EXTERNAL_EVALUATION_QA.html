1 Project Overview & Scope

Project ka naam kya hai aur ye kya karta hai?
Smart QR Attendance System (SQAS) ek web-based attendance management system hai jisme teacher har class ke liye ek time-limited QR code generate karta hai aur students apne mobile se scan kar ke attendance mark karte hain — sab kuch real-time, geo-fenced aur device-bound.
Scope kya hai? Project mein kya kya cover hota hai?
Three user roles (Admin, Teacher, Student), full CRUD for students/teachers/subjects/timetable, QR-based attendance with one-time tokens, GPS geofencing, device binding, role-based dashboards, attendance reports/exports, and a settings module for university configuration.
Scope se bahar (out-of-scope) kya hai?
Native mobile app (we built a mobile-friendly web app instead), biometric verification, payroll/fee management, learning management features (assignments, grades, courses content) — ye intentionally exclude kiye gaye taake project attendance par focused rahe.

2 Problem Statement & Objectives

Problem statement — ye system kyun banaya?
Traditional roll-call attendance time-consuming hota hai (5–10 min per class), proxy attendance ka risk hota hai, paper registers easily lose/tamper ho sakte hain, aur reports nikalna manual aur slow process hota hai. SQAS in sab problems ko ek single, fast, secure aur auditable workflow se solve karta hai.

Objectives

  • Speed: Pura class ki attendance <60 seconds mein.
  • Anti-proxy: Device binding + GPS geofence + one-time QR token.
  • Transparency: Students apni attendance live dekh sakte hain.
  • Reporting: Admin/teacher per-subject, per-date, per-student reports nikal sakte hain.
  • Scalability: Cloud-native architecture — serverless functions + managed Postgres.
Target users kaun hain?
University of Sargodha Department of IT, Semester 8 (BSIT-R0-2022) ke 5 subjects ke teachers aur students. System generic hai — aur batches/departments ke liye easily configure ho sakta hai.

Next.js hi kyun, plain React ya MERN kyun nahi?
Next.js mein frontend aur backend ek hi project mein hote hain — API routes ke liye separate Express server nahi banana padta. Server-side rendering SEO aur first-load speed improve karta hai. Plus Vercel par one-click deploy hota hai.
Supabase kyun, MongoDB ya MySQL kyun nahi?
Supabase = managed Postgres (relational, ACID-compliant) + auto REST/GraphQL APIs + Row-Level Security + free tier. Attendance data relational hai (students ↔ subjects ↔ timetable ↔ attendance) — SQL joins isi ke liye banaye gaye hain. MongoDB document-store hai, relational queries mein slow.
Tailwind CSS ka faida?
Custom CSS files maintain nahi karne padte. Class names directly JSX mein likhte hain (bg-teal-500 px-4 py-2). Design tokens consistent rehte hain, dark-mode built-in, aur production bundle bohot chhota (sirf used classes ship hoti hain).
JWT vs session-cookies?
JWT stateless hai — server pe session table nahi chahiye. Token mein hi user ka id, role, name sign karke encode karte hain. Verify karna fast aur stateless — scale karna easy. HttpOnly cookie mein store karte hain taake JavaScript XSS attack se token leak na ho.

4 System Architecture

Architecture kis pattern par based hai?
Three-tier serverless architecture: (1) Presentation Layer — Next.js React pages (client + server components), (2) Application Layer — Next.js API routes (serverless functions on Vercel), (3) Data Layer — Supabase PostgreSQL with Row-Level Security.

Data flow (simplified)

Browser (React)
      ↓  HTTPS (cookies w/ JWT)
Next.js API Route  (serverless function on Vercel)
      ↓  Service-role key
Supabase Postgres  (RLS-protected tables)
      ↓
JSON Response  →  React state  →  UI re-render
Client-side aur server-side rendering ka kya use kiya?
Login, public pages — server-rendered for SEO/speed. Authenticated dashboards (admin/teacher/student) — client components ('use client') because they need real-time polling, browser APIs (camera, geolocation), aur interactivity.

Total 9 tables. Description below:

Relationships kaise design ki gayi hain?
Foreign keys + ON DELETE CASCADE/SET NULL use kiye gaye hain. Example: agar teacher delete ho, uske subjects ka teacher_id NULL ho jata hai (subject preserved); agar timetable slot delete ho, uske attendance records cascade delete ho jaate hain.
Normalization kis level pe hai?
3NF (Third Normal Form). No redundant data — subject ka naam sirf subjects table mein hai, attendance sirf subject_id reference karta hai. JOIN queries se data combine hota hai.
UNIQUE constraints kahan lagaye?
  • students.enrollment_no — duplicate enrollment prevent.
  • attendance(student_id, timetable_id, date) — ek hi class ka ek hi din do attendance nahi.
  • qr_token_scans(qr_token_id, student_id) — same QR same student replay nahi kar sakta.
  • qr_tokens.token — har QR token globally unique.

Role-based access control (RBAC) kaise enforce hota hai?
Login pe JWT mein role claim sign hota hai. Har API route getSession() call karke role check karta hai. Example: /api/attendance — agar role=student, query mein student_id = session.id hard-coded inject hota hai — doosre student ka data dekhne ka possibility hi nahi.

7 Core Workflow — QR Lifecycle

Step-by-step (one class)

  1. Teacher login → "Take Attendance" page khulta hai.
  2. System auto-detects today's active or upcoming slot from timetable.
  3. Teacher "Generate QR Code" press karta hai.
  4. API call to /api/qr/generate: backend ek unique token (SQAS-…) create karta hai, DB mein expires_at = now + 15 min ke saath save karta hai, aur teacher ko return karta hai.
  5. Frontend QR image render karta hai (QR ka payload deep-link URL hota hai: https://…/student/mark-attendance?token=XXX).
  6. Student apne phone se QR scan karta hai — phone ka native camera ya app dono kaam karte hain.
  7. URL khulta hai, student logged in nahi to login page redirect hota hai, login ke baad auto-submit fires.
  8. API call to /api/qr/verify: backend 6 checks run karta hai (token exists, not expired, within class window, geofence, device binding, no replay).
  9. Sab checks pass → attendance row insert ho jaati hai aur teacher ke screen pe live 5-second polling se attendee list update ho jaati hai.
Grace window: Teacher class start hone se 10 min pehle aur end ke 15 min baad tak QR generate kar sakta hai. Iske bahar request reject — "Class window closed".

8 Security Features

Proxy attendance kaise prevent hoti hai?
Multi-layered defense: har attendance request 6 independent checks se pass hoti hai.
#CheckHow It Works
1Token validityQR token DB mein exist karna chahiye aur expires_at future mein hona chahiye.
2Class time windowToken sirf class start time − 10 min se end time + 15 min tak valid.
3GeofenceStudent ka GPS coordinate university center se configured radius (200 km exhibition demo) ke andar hona chahiye.
4Device bindingStudent ki first attendance pe uske device ka device_id (localStorage UUID) save hota hai. Aage se sirf wahi device accept hota hai.
5One-time replay blockqr_token_scans table mein UNIQUE(token_id, student_id) — ek student ek QR sirf ek baar use kar sakta hai.
6Duplicate-day blockattendance table mein UNIQUE(student_id, timetable_id, date) — ek class ka ek din ek hi entry.

Auth security

  • Passwords bcrypt se hash hote hain (cost factor 10) — DB leak ho bhi to plain passwords expose nahi hote.
  • JWT HttpOnly cookie mein store — JS access nahi, XSS-safe.
  • Cookie SameSite=Lax + Secure — CSRF aur HTTPS-only.
  • JWT 7-day expiry, server-side verify on every request.

Database security

  • Row Level Security (RLS) enabled on every table.
  • API routes service-role key se Supabase call karte hain (server-side only) — client kabhi DB directly access nahi karta.
  • SQL injection impossible because of Supabase parameterized queries.
  • NEXT_PUBLIC_SUPABASE_URL public; SUPABASE_SERVICE_ROLE_KEY sirf server env mein.

9 Deployment & DevOps

Project kahan deployed hai aur kaise?
Vercel par deployed — GitHub repo ke main branch se auto-deploy. Database Supabase cloud par managed Postgres. Domain free *.vercel.app ya custom domain attach ho sakta hai. SSL auto-provisioned (Let's Encrypt).
CI/CD pipeline kya hai?
Push to main branch → Vercel webhook fire → npm run build → type-check + lint + Next.js production build → deployed to edge network. Failed build deploy block kar deti hai. Rollback one-click se possible.
Environment variables kahan manage hote hain?
Vercel dashboard mein 4 env vars: NEXT_PUBLIC_SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, JWT_SECRET, TZ (Pakistan timezone fix). Local dev mein .env.local file use hoti hai (gitignored).

Timezone handling

Vercel servers UTC mein chalte hain. Initially Pakistan se 5 hours behind dates aa rahe the. Fix: Asia/Karachi timezone explicitly use kiya gaya date calculations mein.

10 Testing & Validation

Testing approach kya tha?
Manual testing primarily — teacher + 3 student test accounts ke saath end-to-end flow run kiya gaya. Edge cases: expired QR, wrong location, device mismatch, replay attempt, weekend access, simultaneous scans — sab cases handle hote hain.
Performance testing?
Vercel analytics dashboard se measure kiya. Avg API latency ~150ms. QR generation ~80ms. Page first-paint <1.5s on 4G. Real-time polling 5-second interval pe runs — ~12 requests/min/teacher peak load.

Validation strategy

  • Client-side: form validation, location permission check before submit.
  • Server-side (authoritative): JWT verify, role check, geofence math, time-window check, DB unique constraints.
  • Database-side: UNIQUE constraints, foreign-key integrity, NOT NULL on required fields.

13 Likely Examiner Questions

Agar student ka GPS off ho to kya hoga?
Browser geolocation API permission denied return karega. Backend par lat/lon NULL aayenge — geofence check fail → attendance reject with message "Location required."
Agar student naya phone le aaye?
Admin /api/students/device-reset route se uska device_id clear kar sakta hai. Next login pe naya device bind ho jayega. Audit log mein change visible.
Agar internet slow ho aur QR window expire ho jaye?
Frontend countdown timer show karta hai. Expire hone par token frontend pe disable, backend bhi reject karta hai. Teacher Refresh button se naya QR generate kar sakta hai — baki attendances preserved.
QR ki image hi screenshot le ke share kar di to?
3 layers block karte hain: (1) QR 15 min mein expire ho jaata hai, (2) ek student same QR sirf ek baar use kar sakta hai, (3) doosre student ke device pe device-binding fail hogi (uska device_id kisi aur ka tha).
Database backup kaise hoga?
Supabase daily automated backups deta hai (point-in-time recovery free tier mein 7 days). Admin manually bhi pgdump le sakta hai.
Concurrent users kitne handle kar sakta hai?
Vercel serverless — auto-scales 100s of concurrent requests. Supabase free tier 60 concurrent connections (with pooling). Ek typical class ~30 students simultaneously = comfortably under limits.
Aapne AI / ChatGPT ka use kiya?
Haan, Claude Code (Anthropic ka AI coding assistant) use kiya UI components scaffolding, error debugging aur SQL schema design ke liye. Saari logic aur architecture decisions team ne kiye — AI tool tha, author nahi.
Project ki USP (unique selling point) kya hai?
Existing solutions ya QR-only hain (proxy possible) ya hardware-based (mehnga). SQAS QR + GPS + Device binding teeno layers ek hi flow mein combine karta hai, free hosting par, mobile install ke bina — sirf browser chahiye.
Code maintainability kaise ensure ki?
TypeScript strict mode, ESLint config, modular file structure (api/, lib/, app/), separation of concerns — auth logic lib/auth.ts, DB client lib/supabase.ts, business logic API routes mein.
Documentation aur project deliverables?
README.md, SQL schema files (commented), inline JSDoc comments on critical functions, deployed live link, GitHub repo with commit history, aur ye Q&A document plus presentation slides.
